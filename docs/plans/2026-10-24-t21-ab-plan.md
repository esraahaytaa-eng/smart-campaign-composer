# T21 A/B Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional A/B test: two versions of a campaign's message, a deterministic 50/50 split per language, and a per-version delivery report with real data only.

**Architecture:** A `variant` dimension on content (`a`/`b`, existing content is `a`) and on messages (fixed at build, like language in D64). One extra statement in the audience build assigns versions; dispatch picks the text by the message's language and version. Approval stays per language (D66).

**Tech Stack:** Go, Postgres (goose migrations), Vue 3/TS, vitest, Playwright.

**Spec:** `DECISIONS.md` D68 (with D31, D64, D66, D67), `CASE.md` §9.

## Global Constraints

- A/B is off by default; a campaign without it behaves exactly as today (same API answers, same messages, `messages.variant` NULL).
- No AI call except "Write version B with AI"; it writes only B, only for the selected languages, counts toward the AI-call limit (D63), and rewriting B needs `replace` (D66).
- Not on resends (D31): 409.
- Report: real delivery data only. No opens, clicks, conversions, rates of either, or a winner field.
- Every recipient gets one version on all channels; retries reuse it.
- The rollback of the new migration keeps version A.
- TDD per step; `make test`, `make lint`, `make scan`, `make e2e` green before each task's commit.

## Review Focus

1. **Small and odd audiences:** 1, 2, 3 recipients in a language → split 1/0, 1/1, 2/1; nobody unassigned.
2. **A recipient on one channel only** (no phone): still one version, counted once in the per-language split.
3. **Language fallback + A/B:** a fallback recipient gets the default language's A or B, never a missing text.
4. **Turning A/B off after writing B:** B is kept, not sent, not validated; approval doesn't wait for it.
5. **Old campaigns and in-flight sends during the upgrade:** content rows become `a`; messages with NULL variant send A.

---

## API shape (backward compatible)

- `GET /api/campaigns/{id}`: adds `ab_test` (bool) and `content_b` (same shape as `content`; omitted when empty). `content` stays version A.
- `PUT /api/campaigns/{id}/content`: optional `content_b`, same shape and validation as `content`. Absent = B unchanged.
- `PUT /api/campaigns/{id}/ab` `{enabled, version}`: drafts only, not resends.
- `POST /api/campaigns/{id}/content`: optional `"variant": "b"`.
- `GET /api/campaigns/{id}/estimate` and the review's `delivery`: per version when A/B is on.
- Delivery status (events stream and `GET`): adds `by_variant` per channel when A/B is on.
- `GET /api/campaigns/{id}/recipients`: `variant` column; `variant=a|b` filter (anything else 422).

### Task 4: Assignment and sending

**Files:** `internal/worker/{queue.go,dispatch.go}`, tests in `internal/worker/variant_test.go`

- In `BuildAudience`, after the per-channel inserts and only when `ab_test`, in the same transaction:

```sql
UPDATE messages m SET variant = CASE WHEN r.n % 2 = 1 THEN 'a' ELSE 'b' END
FROM (SELECT user_id, row_number() OVER (PARTITION BY language ORDER BY md5($1::text || ':' || user_id), user_id) AS n
      FROM (SELECT DISTINCT user_id, language FROM messages WHERE campaign_id = $1) u) r
WHERE m.campaign_id = $1 AND m.user_id = r.user_id
```

- Dispatch's content join adds `AND cc.variant = coalesce(m.variant, 'a')`.

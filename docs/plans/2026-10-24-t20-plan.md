**Method:**
- TDD for every change (Red → Green → Refactor), small commits.
- Focused tests while working; `make test`, `make lint`, `make scan` and `make e2e` at the end of each task that changes behaviour.
- Every commit and push is scanned first (D50, D51).
- Each task ends with a short report; anything that needs a decision comes to you first.

**Goal:** each recipient gets the campaign in their own language when the campaign has it, otherwise in the campaign's default language. A/B testing is evaluated and not built.

**Architecture:**
- **Content:** a set of language variants (`tr`, `en`, `de`, each optional) that share the campaign's channels, plus `campaigns.default_language`, which must have a complete variant.
- **Sending:** the worker sends each recipient the variant for their language, else the default. The choice is fixed when the audience is built.
- **Legacy:** content written before T20 is labelled "language not recorded" (`und`) and keeps going to everyone, as today.
- **AI:** one AI call writes the selected variants, so the D63 limit counts it once.

**Tech stack:** unchanged (Go, Postgres, Vue 3, the existing Claude client and mock). No new dependencies.

## Content generation rules

The AI writes message content only when the marketer clicks "Write with AI". Nothing else calls it, and nothing else rewrites content.

| The marketer… | AI content call? | Existing content |
|---|---|---|
| clicks "Write with AI" with languages that have no version yet | one call for those languages | other versions untouched |
| clicks "Write with AI" with a language that already has a version | only after a confirmation naming the versions that will be replaced; the server also refuses without `replace: true` | only the named versions are replaced |
| edits the brief (D40) | none (D40's re-interpretation of the audience is a separate AI call, made only when the marketer saves the new brief) | kept; every version flagged "may be outdated" (I) |
| changes the audience rules or segment | none | kept; the estimate refreshes |
| ticks or unticks languages in the picker | none | kept; the picker only chooses what the next "Write with AI" writes |
| changes the default language | none | kept |
| edits text by hand | none | saved as edited |
| removes a language version | none | that version only, after a confirmation; the default can't be removed |
| removes a channel (J) | none | kept in every version but left out of approval, the estimate and delivery; restored when the channel is chosen again |

**Adding a language after content exists:**
1. The marketer ticks only the new language (the ones already written show "written" and stay unticked) and clicks "Write with AI".
2. Any unsaved edits are saved first.
3. One call writes the new language only.
4. The server stores just that version and keeps every other version unchanged, including manual edits and their "may be outdated" flags.
5. The editor fills in the new tab only.

"Add language → write it myself" creates an empty version with no AI call.

## Global constraints

- The AI never receives customer data (D15): it gets the brief, the channels and the selected language codes, never users or counts per user.
- Only `{{first_name}}`, `{{last_name}}` and `{{city}}`; SMS ≤ 160, subject ≤ 80 and email body ≤ 2,000 characters after personalization, in every variant (D3).
- AI output is untrusted: every variant goes through `ValidateDraft`, and a missing, extra or mislabelled language is a validation error, retried once like today and never filled in silently.
- Languages for new content are exactly `tr`, `en`, `de`; `und` exists only on legacy campaigns. Anything else is refused with `422`.
- UI text in English and Turkish only (D58). German appears only in message content.

## Review focus

The likely failures no task's main path covers, each pinned by a test in the task named:
1. **A pre-T20 approved or sending campaign** sends exactly what it sent before, to everyone (Task 2 migration test, Task 4 worker test).
2. **A non-default language is removed after generation:** its speakers move to the default, and the estimate and preview follow. Removing the default itself is refused until another default is chosen (Tasks 2, 3, 6).
3. **The default variant is incomplete** (a chosen channel is missing or invalid): approval is blocked with the language named. A complete non-default variant does not make up for it (Task 2).
4. **A channel is removed after generation:** its text stays in every version, invalid text there does not block approval, and no message is built for it; choosing it again restores the text (Tasks 2, 4).
5. **The AI returns a missing, extra or mislabelled language:** validation error, one retry, then the same error UI as today (Task 5).
6. **A recipient's language changes after the audience is built:** they still get the recorded language (Task 4).
7. **Unsaved hand edits in one language when "Write with AI" runs for another:** the edits are saved first and kept, and the new language is merged in (Tasks 5, 6).
8. **A settings change that silently costs AI calls:** a brief, rule, language, default, text or channel change makes no content call (Tasks 2, 5, 6).

## Deferred enhancements

**Trade-off** (figures in `2026-10-24-t20-ai-cost.md`): each selected language adds a full set of messages to the AI's answer, so output tokens and AI cost grow roughly in line with the number of languages; the brief and instructions are sent once per call. T20 keeps cost under the marketer's control: explicit selection, one call, and the D63 hourly limit. The ideas below would add value but also scope, so they are recorded rather than built:
- **Automatic language recommendations:** pre-select languages above a share of the audience, or suggest the default from the largest group.
- **AI cost optimization:**
  - prompt caching for the fixed instructions;
  - showing an estimated token cost before writing;
  - writing one language and translating the rest with a cheaper model;
  - regenerating a single variant without the others' context.
- **Per-marketer cost reporting**, beyond the D63 call limit; first step: record tokens per generation as metrics.
- **Retry only the language that failed validation**, instead of the whole combined answer.
- **Lower effort or a cheaper model for content only**, each after a quality check on Turkish and German copy.

## Not in T20

- An audience rule for language ("only German speakers"): not asked for, and the catalog (D14) would need a new field.
- More UI languages: German is content only.
- Automatic translation of a marketer's edits from one variant to another.
- Exploratory QA (T19 Step 8): after all feature work.

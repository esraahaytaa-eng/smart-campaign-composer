# T20 — Product bonuses

**Status:** proposed 2026-10-24 (revision 2), waiting for approval. Nothing is built until decisions A–H are approved and recorded (D64, D65).

**Revision 2 (your feedback):** English is no longer required. Every campaign needs at least one complete language variant and a default language chosen by the marketer, which is also the fallback. Only the selected languages are written. Legacy content is no longer assumed to be English.

**Sources:** `CASE.md` §9 (optional features: A/B testing, messages in the user's language); `DECISIONS.md` D3, D14, D15, D31, D32, D50 (T20 scope), D63; the code on `main` at `256252f`.

**Branch:** `feature/t20-product-bonuses` from `main`, one draft PR, merged only with your approval. T19 Step 8 (exploratory QA) stays postponed until all feature work is done.

**Method:**
- TDD for every change (Red → Green → Refactor), small commits.
- Focused tests while working; `make test`, `make lint`, `make scan` and `make e2e` at the end of each task that changes behaviour.
- Every commit and push is scanned first (D50, D51).
- Each task ends with a short report; anything that needs a decision comes to you first.

**Goal:** each recipient gets the campaign in their own language when the campaign has it, otherwise in the campaign's default language. A/B testing is evaluated and not built.

**Architecture:**
- **Content:** a set of language variants (`tr`, `en`, `de`, each optional) that share the campaign's channels, plus `campaigns.default_language`, which must have a complete variant.
- **Sending:** the worker sends each recipient the variant for their language, else the default. The choice is fixed when the audience is built.
- **Legacy:** content written before T20 is labelled "language not recorded" (`und`) and keeps going to everyone, as today.
- **AI:** one AI call writes the selected variants, so the D63 limit counts it once.

**Tech stack:** unchanged (Go, Postgres, Vue 3, the existing Claude client and mock). No new dependencies.

## Decisions needing your approval

|---|---|---|---|
| A | **At least one complete variant, and a default language picked by the marketer.** Turkish, English and German are each optional. The default must have a complete variant (every chosen channel), and it is the fallback for every recipient whose language has no variant. The default variant can't be removed until another one is made the default. | *English always required (revision 1):* forces an English version on campaigns whose audience doesn't need one. | D64 |
| B | **The marketer selects the languages; only those are written.** The content screen shows the audience's share per language and pre-ticks the languages that have speakers, but writes nothing until the marketer confirms. The default is pre-filled with the selected language that has the most recipients, and the marketer can change it. | *Write every audience language automatically:* spends AI calls and review time on languages the marketer may not want. | D64 |
| C | **One AI call writes all the selected variants.** "Add German" later writes German alone and keeps the other variants. | *One call per language:* up to 3 of the 10 hourly AI calls (D63) per campaign, and the variants can drift apart. | D64 |
| D | **German speakers in the demo data: 5% of users** (`id % 20 = 0`, 150 of 3,000). Fresh databases get them from the seed generator; existing ones from a migration using the same rule. No other seeded value changes. | *Fresh databases only:* your local data would have no German speakers without `down -v`, which deletes your campaigns. | D64 |
| E | **The language is fixed when the audience is built** (`messages.language`): the recipient's own language if the campaign has it, else the default. Retries and the results screen use that choice. | *Chosen on each attempt:* a retry could switch language mid-send, and the results couldn't say what was sent. | D64 |
| F | **Legacy content keeps its behaviour without a guessed language.** Content written before T20 becomes one variant labelled `und` ("language not recorded"), which is also the campaign's default. Everyone keeps getting it, exactly as today. A legacy draft can be relabelled Turkish, English or German, which turns it into a normal campaign; approved, sending and finished campaigns are never changed. `und` is never written by the AI and never offered for new campaigns. | *Label it English (revision 1) or guess its language:* wrong for Turkish content, and a guess could change what an approved campaign sends. | D64 |
| G | **A/B testing is not built.** The system records delivery but no outcome (no opens, clicks or orders after a send), so a winner can't be measured. Building it would double the content model on top of languages for a number nobody can read. The evaluation is recorded instead. | *Build A/B with a delivery-only report:* it looks finished but answers nothing. | D65 (Deferred) |

## Global constraints

- The AI never receives customer data (D15): it gets the brief, the channels and the selected language codes, never users or counts per user.
- Only `{{first_name}}`, `{{last_name}}` and `{{city}}`; SMS ≤ 160, subject ≤ 80 and email body ≤ 2,000 characters after personalization, in every variant (D3).
- AI output is untrusted: every variant goes through `ValidateDraft`, and a missing, extra or mislabelled language is a validation error, retried once like today and never filled in silently.
- Languages for new content are exactly `tr`, `en`, `de`; `und` exists only on legacy campaigns. Anything else is refused with `422`.
- UI text in English and Turkish only (D58). German appears only in message content.

## Review focus

The likely failures no task's main path covers, each pinned by a test in the task named:
1. **A pre-T20 approved or sending campaign** sends exactly what it sent before, to everyone (Task 2 migration test, Task 4 worker test).
2. **A non-default language is removed after generation:** its speakers move to the default, and the estimate and preview follow. Removing the default itself is refused until another default is chosen (Tasks 2, 3, 6).
3. **The default variant is incomplete** (a chosen channel is missing or invalid): approval is blocked with the language named. A complete non-default variant does not make up for it (Task 2).
4. **A channel is removed after generation:** it disappears from every variant (Task 2).
5. **The AI returns a missing, extra or mislabelled language:** validation error, one retry, then the same error UI as today (Task 5).
6. **A recipient's language changes after the audience is built:** they still get the recorded language (Task 4).

### Task 2 — Content variants and the default language: storage, validation, API (A, F)

**Files:** create `internal/db/migrations/00007_content_language.sql`; modify `internal/content/template.go`, `internal/campaign/content.go`, `internal/campaign/http.go`, `internal/campaign/approve.go`; tests next to each.
- **Migration:**
  - `campaign_content.language text NOT NULL CHECK (language IN ('tr','en','de','und'))`, primary key `(campaign_id, channel, language)`.
  - `campaigns.default_language text CHECK (default_language IN ('tr','en','de','und'))` (`NULL` until content is first saved).
  - Existing content rows and their campaigns get `und` (F).
- **Interfaces (later tasks use these):**
  - `type Lang = string`
  - `var Langs = []Lang{"tr", "en", "de"}` (`LegacyLang Lang = "und"`)
  - `type Variants map[Lang]Content`
  - `func ValidateVariants(v Variants, channels []string, def Lang) []FieldError`. Rules:
    - at least one variant;
    - `def` names one of them;
    - keys are a subset of `Langs`, or exactly `{und}`;
    - `ValidateDraft` on each variant (a non-default variant must also be complete, so a recipient never gets half a message).

    Fields are prefixed with the language (`"de.sms.body"`); the field for a missing default is `"default_language"`.
- **API:**
  - `PUT /api/campaigns/{id}/content` takes `{version, default_language, content: {"tr": {sms, email}, "de": {...}}}`; `GET` returns the same.
  - Relabelling a legacy draft is a `PUT` whose variant key changes from `und` to a real language.
  - Approval re-runs `ValidateVariants`.
  - Removing a channel (http.go:264) already deletes it for every language; a test pins that.
- **Tests:**
  - `TestValidateVariants_*`: none at all; default missing or not among the variants; unknown language; `und` mixed with others; a bad field in a non-default variant; all valid with only German.
  - `TestContent_SaveLoadVariants`.
  - `TestContent_RelabelLegacyDraft`.
  - `TestEdit_RemovingChannelDropsItFromEveryVariant`.
  - `TestApprove_IncompleteDefaultBlocked`.
  - `TestMigrate_LegacyContentBecomesUnd`.

### Task 4 — Send in the recipient's language (E)

**Files:** create `internal/db/migrations/00008_message_language.sql`; modify `internal/worker/queue.go` (`buildOne`), `internal/worker/dispatch.go` (`load`), the resend path in `internal/campaign/approve.go`; tests in `internal/worker`, `internal/e2e`.
- **Migration:** `messages.language text` (`NULL` on rows built before T20).
- **Build:** at audience build, `language = CASE WHEN u.language = ANY(<campaign's variants>) THEN u.language ELSE c.default_language END`.
- **Load:** joins `campaign_content` on `coalesce(m.language, c.default_language)`. Messages built before T20 thus reach the legacy `und` row, unchanged.
- **Over-limit:** the skip at send time uses the chosen variant.
- **Resend (D31):** the resend campaign pre-selects the languages recorded on the skipped messages (for a legacy parent, the recipients' own languages). It pre-fills the parent's default when that is a real language, otherwise the largest selected language. The marketer confirms in the content screen, and Task 5 writes the shorter variants.
- **Tests:**
  - `TestBuild_LanguageChosenPerRecipient`: `tr` with a Turkish variant; `de` with no German variant → the default; a default of German.
  - `TestProcess_SendsChosenVariant`.
  - `TestProcess_LanguageChangeAfterBuildKeepsChoice`.
  - `TestProcess_PreT20MessageSendsLegacyContent`.
  - `TestResend_PreselectsSkippedLanguages`.
  - In `internal/e2e`: a send with Turkish and German variants, default Turkish, through the mock provider. German speakers get German, Turkish speakers Turkish, English speakers Turkish.

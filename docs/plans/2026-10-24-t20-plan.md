# T20 — Multilingual messages

**Status:** final proposal 2026-10-24, waiting for approval. Nothing is built until decisions A–J are approved and recorded in DECISIONS.md. Earlier revisions (German, English mandatory, no recommendations, a warning-only flag) are replaced by this one; see the Git history of this file.

**Sources:** `CASE.md` §9 (optional features: A/B testing, messages in the user's language); `DECISIONS.md` D3, D14, D15, D30, D31, D32, D38, D39, D40, D48, D50, D63; `docs/plans/2026-10-24-t20-ai-cost.md`; the code on `main` at `256252f`.

**Branch:** `feature/t20-product-bonuses`, one draft PR, merged only with your approval. T19 Step 8 (exploratory QA) stays postponed until all feature work is done.

**Method:**
- TDD for every change (Red → Green → Refactor), small commits.
- Focused tests while working; `make test`, `make lint`, `make scan` and `make e2e` at the end of each task that changes behaviour.
- Every commit and push is scanned first (D50, D51).
- Each task ends with a short report; anything that needs a decision comes to you first.

**Goal:** each recipient gets the approved message in their language (Turkish or English), otherwise in the campaign's default language. The data model takes more languages later without restructuring.

**Architecture:**
- **Catalog:** one language catalog in Go (code and native name) is the only list of languages, served to the UI through the existing catalog API (D39).
- **Content:** stored per channel and language. A small per-language record holds each language's review state.
- **Default language:** `campaigns.default_language` names the fallback.
- **Sending:** the worker picks each recipient's language when the audience is built.
- **AI:** writes only the selected languages, in one call.

**Tech stack:** unchanged (Go, Postgres, Vue 3, the existing Claude client and mock). No new dependencies.

## Behaviour rules

**AI calls:** only "Write with AI" writes content.

| The marketer… | AI content call? | Existing content |
|---|---|---|
| clicks "Write with AI" for languages without content | one call for those languages | other languages untouched |
| clicks "Write with AI" for a language that has content | only after a confirmation naming it; the server refuses without `replace: true` | only that language replaced, then needs review |
| saves a new brief (D40) | none (the audience is recalculated by the existing interpretation call) | kept; every language set to needs review, "may be outdated" |
| changes rules, languages ticked, the default, or text | none | kept (edited text → needs review) |
| removes a language | none | that language only, after a confirmation; the default can't be removed |
| removes a channel (H) | none | kept, left out until the channel is chosen again |

**Adding a language after content exists:**
1. The marketer ticks only the new language (written languages show "written" and stay unticked) and clicks "Write with AI".
2. Pending edits are saved first.
3. One call writes the new language.
4. The server stores only that language and keeps the others exactly as they were (text, review state, warnings).
5. The new language starts as needs review.

"Add language → write it myself" creates an empty version with no AI call.

**Counts shown** (audience step, content screen, final review):
- For each channel, recipients who will get each language, split into own-language speakers and fallback recipients. For example: "SMS · Turkish 2,430 (2,190 Turkish speakers + 240 English speakers, default) · English 0".
- The same split is used for the over-limit estimate per language.

## Global constraints

- The AI never receives customer data (D15): it gets the brief, the channels and the selected language codes.
- Only `{{first_name}}`, `{{last_name}}`, `{{city}}`; SMS ≤ 160, subject ≤ 80, email body ≤ 2,000 characters after personalization, in every language, at approval and at send time (D3).
- AI output is untrusted: every language goes through `ValidateDraft`. A missing, extra or mislabelled language is a validation error, retried once and never filled in silently.
- New content uses only catalog languages; `und` exists only on legacy campaigns; anything else is `422`.
- UI text stays in English and Turkish (D44, D58); language names come from the catalog in their own language.

## Review focus

The likely failures no main path covers, each pinned by a test in the task named:
1. **Pre-T20 campaigns:** a pre-T20 approved or sending campaign sends exactly what it did before, and a legacy draft can still be approved (Tasks 1, 4).
2. **An edit after a language is approved** puts it back to needs review, and campaign approval is refused until it is approved again (Task 2).
3. **A brief saved after approval of a language:** its text is unchanged, it needs review again, and no content call is made (Task 2).
4. **A recipient whose language has no content** gets the default; the counts and the estimate show them as fallback (Tasks 3, 4).
5. **A removed channel with invalid text** doesn't block approval and gets no messages; choosing it again restores the text (Tasks 1, 4).
6. **The AI returns a missing, extra or mislabelled language:** validation error, one retry, then the existing error UI (Task 5).
7. **Unsaved edits in one language** when "Write with AI" runs for another are saved first and kept (Tasks 5, 6).

## Deferred enhancements

**Trade-off** (figures in `2026-10-24-t20-ai-cost.md`): every selected language adds a full set of messages to the AI's answer, so output tokens, about 95% of the cost, grow with each language. T20 keeps cost in the marketer's hands: a recommendation they confirm, generation only of selected languages, one call, no calls on settings changes, and the D63 hourly limit.

Later, if needed:
- more languages (catalog entry, migration, mock texts);
- reusing approved content across campaigns;
- recording tokens per generation as metrics (the first step toward any cost decision);
- retrying only the language that failed validation;
- lower effort or a cheaper model for content, after a quality check;
- per-marketer cost reporting.

- An audience rule for language ("only English speakers"): not asked for; the catalog of rules (D14) would need a new field.
- German or other content languages (the design supports them; see Future improvements).
- Automatic translation of edits from one language to another.

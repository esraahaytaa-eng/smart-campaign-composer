# T20 — AI cost analysis for multilingual content

**Status:** estimate for the T20 plan (`2026-10-24-t20-plan.md`), 2026-10-24. T20 supports Turkish and English, so **2 languages is the T20 maximum**; the 3- and 4-language rows show the cost of adding languages later. No API calls were made. Every token figure is an assumption built from the app's real request, and every figure below should be replaced by measured numbers (see "Confirming the numbers").

## What a content call is today

From `internal/llm/anthropic_content.go`:
- **Model:** `claude-opus-5-5` (the `ANTHROPIC_MODEL` default; the same setting is used for audience interpretation).
- **Thinking:** adaptive, which can't be turned off on Opus 5.5. Thinking tokens are billed as output.
- **Effort:** `medium`.
- **Output:** structured JSON, streamed; `max_tokens` 16,000 (a ceiling, not a cost).
- **Input:** a 934-character system prompt (~230 tokens), the JSON schema, and a user message with the brief. That is about 450 tokens today; the per-language instructions add an estimated ~100.

**Prices** (Anthropic first-party API, per million tokens, from the Claude API reference cached 2026-10-06):

| Model | Input | Output | Cache read | Cache write (5 min) |
|---|---:|---:|---:|---:|
| Claude Opus 5.5 (current) | $4.00 | $20.00 | $0.20 | $5.00 |
| Claude Sonnet 5.5 | $2.00 | $10.00 | $0.20 | $2.50 |
| Claude Haiku 5.5 | $0.10 | $0.50 | — | — |

These must be rechecked on the live pricing page before any budget decision.

## Token assumptions (both channels, one language = SMS + email subject + email body)

| Part | Tokens | Why |
|---|---:|---|
| Input per call | 600 + 30 per language | system prompt, schema, brief, per-language rules |
| Message text per language | ~350 | SMS ≤ 160 chars (~60), subject (~25), body (~240), JSON keys (~25); Turkish and German take more tokens per character than English |
| Thinking per call | ~800 + 200 per language | medium effort on short copywriting; **the least certain figure** |

Output (text plus thinking) is about 95% of the cost, so input-side savings barely matter.

## 2 vs 4 languages, one combined call vs separate calls (Opus 5.5)

Combined: one call writes all N languages. Separate: N calls, one language each (each repeats the prompt, the brief and the base thinking).

| Languages | Combined call: tokens in / out | Combined: cost | Separate calls: cost | Separate costs more by | AI calls counted (D63) |
|---|---|---:|---:|---:|---|
| 1 | 630 / 1,350 | $0.030 | $0.030 | — | 1 vs 1 |
| 2 | 660 / 1,900 | **$0.041** | **$0.059** | +45% | 1 vs 2 |
| 3 (T20's maximum) | 690 / 2,450 | $0.052 | $0.089 | +71% | 1 vs 3 |
| 4 (if a language is added later) | 720 / 3,000 | **$0.063** | **$0.118** | +88% | 1 vs 4 |

- **2 → 4 languages:** about +55% per generation with one combined call (+$0.022), and +100% with separate calls.
- **Per 1,000 generations:** 2 languages about $41 combined vs $59 separate; 4 languages about $63 vs $118.
- **Other models, same tokens (combined, 4 languages):** Sonnet 5.5 about $0.031, Haiku 5.5 about $0.0016.
- **Retries:** a failed validation retries once (D63 counts it).
  - A combined retry rewrites every language, so with a retry rate *r* the expected cost is × (1 + *r*).
  - Separate calls retry only the failing language, the one place where they are cheaper.
- **Ceiling per marketer:** D63 allows 10 AI calls an hour, so at most about $0.63 per marketer-hour with 4 languages combined, retries included.

## Cost-saving opportunities

| Lever | Saving | Status |
|---|---|---|
| Explicit language selection (no automatic extra languages) | Cost grows only with what the marketer asks for | **In T20** (B) |
| One combined call | 30–47% against separate calls at 2–4 languages | **In T20** (C) |
| "Add a language" writes only the new one; settings changes make no call | No repeated calls for languages already written | **In T20** (content generation rules) |
| Retry only the language that failed validation | Retry cost falls from all N languages to one | Deferred: small change, worth doing once retries are measured |
| Lower effort (`low`) for content | Fewer thinking tokens, possibly the largest single cut | Deferred: needs a quality check on Turkish and German copy |
| A cheaper model for content only (Sonnet 5.5 ~½, Haiku 5.5 ~1/40) | Large | Deferred: your decision; needs a quality check. Today one setting covers both AI tasks |
| Write one language, translate the rest with a cheaper model | Large for 3–4 languages | Deferred: adds a second call and a quality risk |
| Prompt caching of the fixed instructions | ~0 today | Not useful: the fixed prefix is ~350–450 tokens, under Opus 5.5's 512-token minimum, and input is ~5% of the cost |
| Batch API (50% off) | — | Not applicable: generation is interactive and streamed |
| Record tokens per generation (input, output, number of languages) as metrics | Replaces these estimates with real numbers | Deferred: the first step before any of the levers above |

## Confirming the numbers

Two ways, both need your approval because they use the API key:
- **Token counting API** (`POST /v1/messages/count_tokens`, no charge) measures the exact input for 1–4 languages.
- **A handful of real generations** in real mode (about $0.30 in total for 1, 2, 3 and 4 languages) gives the actual output and thinking tokens from `usage`.

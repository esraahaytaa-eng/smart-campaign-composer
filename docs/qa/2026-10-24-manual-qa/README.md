## Bugs

### BUG-1 — An empty amount in the rule editor shows a raw server error · Severity: Low
- **Steps:** open any draft → Audience → **+ Add rule** → *Total spend: at least* (or *Spend in a period*) → clear **Amount (TL)** → **Apply**.
- **Expected:** an inline message in the editor ("Enter an amount from 0 to 1,000,000 TL."), and no request sent.
- **Actual:** "The server didn't accept this change. Details from the server (in English): invalid value for total_spend gte: json: cannot unmarshal string into Go …". No bad data is saved; the server rejects it.
- **Cause:** an emptied number input holds `''`, and `'' >= 0` is true in JavaScript, so `formProblems` in `web/src/campaign/rules.ts` lets it through. Count and day fields are not affected because they use `Number.isInteger`.
- **Evidence:** [S4-empty-amount.png](shots/S4-empty-amount.png)
- **Status:** fixed in PR #15, merged into `main` (a `Number.isFinite` guard plus 4 test cases; the new tests failed first and pass with the fix; web tests 429/429, lint and build passed).

## Observations (not bugs; for your decision)
1. The browser console logs a 401 for `GET /api/me` on the sign-in page. This is the normal "am I signed in?" check, but it shows up as noise in the console.
2. Review step: **Approve and send…** looks disabled but explains why only after it is clicked ("Still needed before approval…"). It has no `aria-describedby` for screen readers.
3. `DELETE` on a completed campaign returns **400**, where **409** would describe the conflict more accurately. The UI never offers it.
4. Two-tab conflict: the stale tab correctly refuses the save and offers **Reload**, but its language tab still says "Not written yet" next to the unsaved text.
5. In full-page screenshots the sidebar looks cut off at 1000 px. This is a screenshot artifact: the sidebar is sticky and fills the viewport when you scroll (V1).

     Decision content (approved)

     - D17 — PostgreSQL 16. Why: SKIP LOCKED for leases (D5), char_length = code
       points (D2), schemas + roles for provider separation (D6), ON CONFLICT
       for D4 and idempotent seed, pgx. Rejected: MySQL 8 (weaker schema/role
       split and RETURNING), SQLite (not a server, single writer). Trade-off:
       heavier than SQLite.
     - D18 — Queue = the messages table. Workers claim batches with FOR UPDATE 
       SKIP LOCKED (due pending/retry_scheduled, or sending with expired lease);
       result updates are conditional on the current lease so a stale worker
       cannot overwrite. Why: D5/D7 state already lives there; no dual
       write/outbox; no extra service; 200 msg/s is trivial. Rejected:
       Redis+asynq (extra service, dual write), RabbitMQ/NATS (extra service,
       awkward delayed retry, dual write), River (duplicates our state machine).
       Trade-off: polling loop when idle; a reviewer may expect a broker.
     - D19 — One worker replica with in-process per-channel rate limiter.
       x/time/rate per channel with limit 100/s and burst 1, so attempt starts
       are at least 10 ms apart → never more than 100 provider requests in any
       1-second window, bursts included. Every attempt takes a token right
       before the HTTP call: first sends, retries (D7) and lease-expired resends
       (D5). Bounded goroutine pool per channel; the limiter, not the pool,
       sets the rate. A test asserts that no 1-second window of recorded attempt
       times exceeds 100. API runs as a separate process and can scale
       independently. Rejected: shared Postgres token bucket (DB round-trips,
       more code), static 100/N split (config must match replica count).
       Trade-off: worker cannot scale out without a shared limiter (Deferred).
     - D20 — Component boundaries. One Go module, one image. Compose services:
       postgres; migrate (one-shot migrations + deterministic idempotent seed;
       others wait for service_completed_successfully); api (campaigns,
       approval, Claude, SSE, auth, serves built Vue SPA → same origin); worker
       (sending only); mock-provider (one service, /sms/send + /email/send,
       per-channel env-configured delay/5xx/429+Retry-After/timeout, provider
       schema + own DB role per D6). API and worker communicate only through the
       database. Rejected: nginx frontend container (extra service, SSE proxy
       buffering config), separate SMS/email provider services (duplicate
       service), API+worker in one process (sending would share fate with UI and
       AI). Trade-off: multi-stage Docker build (Node → Go); Vite dev proxy for
       development.
     - D21 — Live updates via SSE. Content generation: POST + fetch streaming
       read. Dashboard: EventSource; API queries per-campaign aggregate counts
       ~1s and pushes on change. Rejected: WebSocket (bidirectional not needed,
       extra library), client polling (second mechanism, less live),
       LISTEN/NOTIFY (notification storms at 200 msg/s). Trade-off: ~1s latency;
       one DB aggregate per open dashboard per second.
     - D22 — Backend libraries. stdlib net/http (1.22 routing), pgx/v5 + pgxpool
       with hand-written SQL, goose with embedded migrations, official
       anthropic-sdk-go (structured JSON output, streaming for content) behind a
       small LLM interface with a mock, hand-written validation (D12–D15),
       x/crypto/bcrypt + opaque session token in HttpOnly SameSite cookie with
       hash stored in DB, x/time/rate, log/slog, env-var config, seed from
       hand-written Turkish name/city lists with a fixed random seed. Rejected:
       gin/echo/chi (not needed), GORM (hides SQL, D14 audits), sqlc (codegen,
       no dynamic WHERE), initdb scripts (fresh volume only), raw HTTP to Claude
       (reimplements SDK), JSON-schema lib (catalog checks are custom anyway),
       JWT (revocation), viper/zap, gofakeit (dependency, not Turkish).
     - D23 — Default model claude-opus-5-5, overridable via ANTHROPIC_MODEL.
       Why: best at interpreting requests correctly. Rejected: Sonnet 5.5
       (cheaper/faster, slightly higher misread risk), Haiku 5.5 (more D15
       retries). Trade-off: higher per-token price and slower streaming than
       Sonnet; actual cost depends on token usage.
     - D24 — Mock LLM by default, real mode opt-in. LLM_MODE=mock is the
       default, so docker compose up runs the full campaign flow without a key;
       the UI shows a visible "Mock AI" banner. LLM_MODE=real uses
       ANTHROPIC_API_KEY; if it is missing, the API exits on startup with a
       clear error naming the variable (fail fast — my call, since real mode is
       an explicit choice). The mock returns schema-valid output and goes
       through the same validation (D15). Rejected: real by default with opt-in
       mock (needs a key or an extra step to try the flow), automatic fallback
       when no key (hides misconfiguration). Trade-off: someone running the
       default sees canned AI output; .env.example and README must say how to
       switch to real mode.
       - History: 2026-10-21. First approved as "clear error, opt-in mock";
         changed to mock-by-default in the same session.
     - D25 — Frontend: Vue 3 + Vite + TypeScript + vue-router + PrimeVue; native
       fetch/EventSource; no Pinia; Vitest. Rejected: no UI library (more
       hand-built components, accessibility risk), Tailwind (still hand-built
       components), Pinia (few screens). Trade-off: large dependency only partly
       used.
     - D26 — Metrics & health. Prometheus text format via
       prometheus/client_golang at /metrics on api, worker and mock-provider:
       send attempts by channel/result, 429 and retry counts, provider latency
